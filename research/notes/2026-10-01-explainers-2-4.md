## Findings for editors (not fixed; outside this assignment)

1. **The Ollama docs disagree on the default context length.** The FAQ says "By default, Ollama uses a context window size of 4096 tokens." The Context length page gives VRAM-based defaults: 4k below 24 GiB, 32k for 24–48 GiB, 256k at 48 GiB or more. The hardware explainer cites the more specific Context length page. Recheck when Ollama updates its docs.
2. **The Granite 4.2 8B card is inconsistent about context.** Its Description lists a "512K Context Window". Its summary says 128K native with long-context extension to 512K. The shipped config.json and the card's vLLM and SGLang examples use 131,072. The catalog record's summary ("supports a 128K-token context natively; the model card documents extension to 512K") is accurate, but "documents extension" may overstate it: this review found no instructions for running at 512K. The 512K figure comes from the Granite 4.1 base model's pre-training.
3. **The Granite 4.2 8B raw README contains editor TODO comments** (for example "TODO: Add pre-training details here") in HTML comments. They are not visible on the rendered page, and the explainer does not mention them. They suggest the card may change again, so cite revision f8de16c for any claims taken from it today.
4. **The Ollama library "Size" column** (14GB for gpt-oss:20b) is presented in the explainer as a download size, not a run-time memory figure. Cloud tags show "Low Usage" and "Medium Usage" in that column instead of a size, which supports this reading. Ollama does not define the column on the page.
5. **The OpenAI Cookbook statement** that gpt-oss ships MXFP4 with "currently no other quantization" dates from August 5, 2025. The explainer gives that date instead of presenting the statement as current.
6. **Cross-links.** The model card explainer does not link `/learn/reading-evaluations/` because that explainer is being written in parallel. Add the link once it is published.
